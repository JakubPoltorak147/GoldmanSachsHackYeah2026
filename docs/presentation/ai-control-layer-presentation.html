How it works

1

Validate

Strict HTTP boundary: exact fields, bounded text, server-owned ID.

2

Evaluate

Registered controls read the original text and return findings, never actions.

3

Decide

Central policy maps findings: BLOCK › REDACT › ALLOW, with safe reasons.

4

Record

A content-free audit event is flushed to stdout and committed to SQLite.

5

Dispatch

ALLOW once, REDACT transformed once, BLOCK zero target calls.

6

Observe

Completion is recorded; the dashboard reads safe evidence only.

If anything fails: invalid inputevaluation erroraudit error zero target calls

Why this design wins

Provider-independent

Core and policy know nothing about a vendor or framework. Swap the target, keep the guarantees.

Fail closed

Invalid input, evaluator error or audit error: zero target calls. Silence never means allow.

Explainable

Every BLOCK and REDACT carries structured finding codes and a safe reason.

Privacy-safe evidence

Audit and dashboard hold metadata only: no prompts, no matched values, no hashes.

Policy-driven

Enforcement lives in one YAML policy per deployment, not hard-coded into every application.

Extensible by registration

New detector or target plugs into the registry. The single orchestrator stays untouched.

Coverage

Eight registered controls. Each one returns findings; central policy maps them to an action.
